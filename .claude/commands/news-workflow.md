# 뉴스 수집기 기능 개발 워크플로우

뉴스 수집기 앱에서 새 기능을 개발할 때 사용하는 명령입니다.
입력받은 브랜치 이름: $ARGUMENTS

아래 과정을 **순서대로** 실행하세요.

## 1. 현재 상태 확인
- `git status`와 `git branch --show-current`로 현재 상태와 브랜치를 확인합니다.
- 현재 브랜치가 `main`이 아니면 **경고**를 보여주고, main으로 이동할지 사용자에게 묻습니다. 사용자의 답을 받기 전에는 다음 단계로 넘어가지 않습니다.
- 커밋되지 않은 변경사항이 있으면 함께 알려줍니다.

## 2. 새 브랜치 만들기
- `$ARGUMENTS`가 있으면 그 이름으로 새 브랜치를 만듭니다 (`git checkout -b <이름>`).
- `$ARGUMENTS`가 비어 있으면 어떤 기능을 개발할 것인지 사용자에게 묻고, 답을 바탕으로 **영어 소문자-하이픈 형식**(예: `add-category-filter`)의 브랜치 이름을 제안합니다. 사용자가 확인하면 그 이름으로 만듭니다.

## 3. 개발 시작 안내
- 브랜치 생성이 끝나면 **"이제 개발을 시작하세요!"** 라고 안내합니다.
- `CLAUDE.md`를 읽고 이 프로젝트의 기술 스택과 컨벤션을 다시 한번 알려줍니다.
  - 기술 스택: Next.js 16(App Router, `src/`), React 19, TypeScript, Tailwind 4, Clerk, Drizzle + Neon Postgres, Anthropic SDK, rss-parser, Notion MCP
  - 컨벤션: Next.js 코드 작성 전 `node_modules/next/dist/docs/` 확인, UI 변경 전 `ui.md` 확인, 범위·데이터 모델은 `PRD.md` 기준, 비밀 값은 서버 전용, 외부 호출 실패는 사용자에게 보이는 에러로 처리
  - 검증 명령: `npm run lint`, `npx tsc --noEmit`, `npm run build`

## 4. 완료 처리
사용자가 **"완료"** 또는 **"done"** 이라고 입력하면:
1. `git status`와 `git diff --stat`으로 변경된 파일 목록을 보여줍니다.
2. 변경 내용을 바탕으로 커밋 메시지를 자동으로 제안합니다 (프로젝트의 기존 커밋 스타일인 한국어 한 줄 요약을 따릅니다).
3. 사용자가 확인하면 변경 파일을 add하고 커밋합니다. (수정을 원하면 반영 후 다시 확인)
4. 커밋 후 `main`으로 이동해 작업 브랜치를 병합합니다 (`git merge --no-ff <브랜치>`). 충돌이 나면 멈추고 사용자에게 알립니다.

## 5. 작업 요약
- 병합이 끝나면 작업 내용을 요약해서 보여줍니다: 브랜치 이름, 커밋 메시지, 변경된 파일, 병합 결과.
