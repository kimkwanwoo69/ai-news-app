# 커밋 전 코드 검토

커밋하기 전에 변경된 코드가 프로젝트 컨벤션을 지키는지, 코드 품질에 문제가 없는지 검토합니다.

## 진행 순서

1. 현재 브랜치에서 변경된 코드를 가져옵니다.
   - `git status`로 변경된 파일 목록을 확인합니다.
   - `git diff HEAD`로 스테이징된 변경과 스테이징되지 않은 변경을 함께 확인합니다.
   - 새로 추가되어 추적되지 않는 파일(`??`)은 내용을 직접 읽어서 검토 대상에 포함합니다.
2. [conventions.md](conventions.md)의 규칙을 기준으로, 변경된 코드의 각 항목을 **통과** 또는 **개선 필요**로 표시합니다.
   - 규칙 하나당 한 줄로, 항목 이름과 판정을 표로 보여 줍니다.
   - 개선 필요 항목에는 문제가 있는 파일과 줄 번호(`파일경로:줄번호`)를 함께 적습니다.
   - 변경된 코드에 해당하지 않는 규칙(예: DB 코드가 없는데 try-catch 규칙)은 **통과**로 표시하고 "해당 없음"이라고 덧붙입니다.
3. **개선 필요** 항목이 있으면 어떻게 고쳐야 하는지 코드 예시와 함께 알려 줍니다.
   - 현재 코드(Before)와 수정 코드(After)를 나란히 보여 줍니다.
   - 코드를 직접 수정하지는 않고, 제안만 합니다.
4. 모든 항목이 **통과**라면 `커밋 준비가 완료되었습니다!`를 출력합니다.

## 출력 형식

```
| 항목 | 판정 | 비고 |
|---|---|---|
| 네이밍 - 변수·함수 카멜 케이스 | 통과 | |
| 코드 품질 - console.log 제거 | 개선 필요 | src/lib/foo.ts:12 |
```
